## 1. Purpose

This document specifies how the **ERC-8040 Blockchain Ecosystem** maps ATF-AI Core primitives into blockchain / ESG digital-asset workflows.

It defines the contract between the ATF-AI Governance Layer and the ERC-8040 adapter. Implementations claiming conformance with this adapter MUST also satisfy the parent ATF-AI Core specification.

If this adapter conflicts with a mandatory ATF-AI Core requirement, the parent specification takes precedence.

---

## 2. Scope

This specification covers:

- conceptual mapping from ATF-AI to ERC-8040;
- smart-contract roles;
- SDK implementations;
- deployment targets;
- supported compliance mappings;
- conformance requirements;
- relationship with companion ATF-AI adapters.

This specification does not cover:

- ATF-AI Core internals;
- every implementation detail of the external ERC-8040 ecosystem repository;
- network-specific production deployment configuration;
- privileged RWA lifecycle governance beyond the mapping defined here.

Privileged RWA lifecycle operations such as redemption, signer changes, oracle changes, upgrades, and settlement authorization are addressed by the companion [`RWA Privileged Action Governance Adapter`](./rwa-privileged-governance.md).

## 4. Smart Contract Architecture

### 4.1 `ERC8040.sol` — Token with Embedded Provenance

**ATF-AI role:** Provenance-record storage + zero-trust token-transfer validation.

Key behaviors:

- token transfers can require a minimum ESG score threshold;
- score updates reference ATF-AI provenance data;
- score history is represented through append-only events/history mechanisms.

### 4.2 `ESGOracle.sol` — Attestation Publisher

**ATF-AI role:** on-chain publication of attestation results.

Key behaviors:

- only registry-authorized providers may publish score updates;
- each accepted update represents an on-chain ATF-AI attestation event;
- historical updates are queryable through emitted state/events.

### 4.3 `ESGRegistry.sol` — Governance and Identity Registry

**ATF-AI role:** governance / authorization registry.

Key behaviors:

- provider registration follows ATF-AI governance;
- provider revocation removes oracle authorization;
- LEI binding can connect blockchain identity with a legal entity identifier.

### 4.4 `ERC8040Factory.sol` — Adapter Interface

**ATF-AI role:** standardized adapter-instantiation interface.

The factory deploys ERC-8040 instances with declared governance parameters.

## 8. Conformance Requirements

An ERC-8040 adapter implementation MUST:

1. implement the declared ERC-8040 smart-contract interfaces;
2. preserve ATF-AI provenance references in the token / attestation workflow;
3. gate oracle updates through declared authorization policy;
4. emit or retain traceable evidence for score/attestation changes;
5. support the declared identity metadata required by the adapter;
6. remain compatible with the parent ATF-AI Core version it declares.

An implementation SHOULD:

1. implement at least one reference SDK interface;
2. support the ISO 20022 bridge where financial-message interoperability is required;
3. validate on a declared testnet before production deployment;
4. adopt the RWA Privileged Action Governance adapter when high-impact admin/redemption/signing operations are in scope.

## 9. Relationship to RWA Privileged Action Governance

ERC-8040 governs the blockchain/ESG digital-asset mapping. The RWA Privileged Action Governance adapter governs **high-impact lifecycle authority around the asset**.

```text
ATF-AI Core
   |
   +-- ERC-8040 Adapter
   |      token / ESG / provenance / compliance mapping
   |
   +-- RWA Privileged Action Governance Adapter
          redemption / admin / signer / oracle / upgrade / settlement policy
```

The companion RWA adapter preserves a key separation:

> A valid signing credential is an execution capability, not sufficient governance authority by itself.

An ERC-8040 implementation MAY adopt the companion adapter without changing the ERC-8040 token interface itself.
